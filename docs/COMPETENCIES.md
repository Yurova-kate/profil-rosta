# Единый справочник компетенций 1С — спецификация

## Принцип
Компетенция определяется одной записью каталога. Названия «СКД» и «Система компоновки данных» — один объект с алиасами, а не два навыка. Сотрудник выбирает запись каталога, а не вводит произвольный текст.

## Сущности
- Competency: id, name, category, description, active.
- CompetencyAlias: id, competency_id, alias (уникальный нормализованный).
- EmployeeCompetency: employee_id, competency_id, level, status, updated_at; уникальная пара employee_id + competency_id.
- CompetencyEvidence: employee_competency_id, source_type, source_id, comment.
- CompetencyVerification: employee_competency_id, manager_id, decision, timestamp, comment.

## Уровни владения
Начальный, рабочий, продвинутый, экспертный. Это **уровень конкретного навыка**, не должностной грейд сотрудника.

## Статусы
Заявлено сотрудником → ожидает проверки → подтверждено / требует уточнения. Изменение уровня после подтверждения требует повторной проверки.

## Категории для первичного наполнения
- Платформа 1С: запросы, СКД, управляемые формы, расширения, БСП.
- Интеграции: HTTP-сервисы, REST, обмены, КД, очереди.
- Конфигурации: 1С:ЗУП, 1С:ERP, 1С:Бухгалтерия, 1С:Документооборот.
- Аналитика: моделирование процессов, постановка требований, тестирование.
- Разработка и сопровождение: отладка, производительность, обновления.

## Права
- Администратор управляет каталогом и алиасами.
- Сотрудник добавляет компетенцию себе, выбирает уровень, прикладывает подтверждения.
- Руководитель просматривает компетенции подчинённых и подтверждает или запрашивает уточнения.
- Редактирование каталога не должно менять историю оценок и подтверждений.

## Интеграции
- Проектное резюме берёт компетенции из EmployeeCompetency, показывая подтверждение.
- Рекомендации по сертификации ссылаются на Competency.id, а не на строковое совпадение.
- Импорт СППР может предлагать компетенции, но не подтверждает их автоматически.

## Критерии приёмки
1. Нельзя добавить одну компетенцию сотруднику дважды, включая алиасы.
2. Изменение уровня снимает прежнее подтверждение.
3. Руководитель не может подтвердить компетенцию чужого сотрудника.
4. В резюме выводятся актуальные названия и уровни.
5. Существующие свободно введённые навыки мигрируются через сопоставление и ручную проверку; не удаляются автоматически.
6. API, UI, БД и тесты внедряются единым вертикальным срезом, без «пустых» элементов.
